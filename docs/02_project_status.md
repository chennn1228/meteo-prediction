- 南京 2024-02 至 2026-08 的三源 93 个月文件均带当前请求侧车；清洗和 39 项正式特征已落盘。与此前旧缓存逐月逐字段对照，南京相同数据值及返回坐标一致。
- 一个真实数据 CPU 最小端到端检查点通过；固定 CPU 七模型在原定五个外折共用每模型 9,564 个可评分白天样本。
- Ridge MOS、LightGBM、XGBoost 的五个外折 × 六候选 × 三内折调参完整完成（270 条成功 trial）。每个外折的候选只由其内部数据选择；树模型逐分位早停轮数从选中候选的三内折取得中位数，然后对该外折的全部拟合样本重训。十个模型的外折预测和评分已落盘。
- 原定最终测试时间顺序完成：拟合至 2025-06-20、7 月独立早停、8 月 11–31 日校准、2025-09-01 至 2026-08-31 测试。测试有 13,266 条白天预测/模型，其中 384 条缺真值，仅 12,882 条/模型进入评分。概率校准只使用预测签发时已知的校准真值。
- 已生成 16 张南京诊断数据、模型、概率与开发期解释图，源数据 CSV、SVG/PDF/PNG 与图注合同同存；图面明确声明不是正式 20 站证据。原始树分位交叉率在外折结果中保留并报告，未以校准结果覆盖它。组消融/组置换均仅用五个外折各自的三个内折；单站常量空间组不参与归因，Base+cloud/kt 对照、稳定性区间仍待做。

## 仍阻断正式 20 站 CPU 重跑的四项

1. 当前临时 15 变量数据根目录要求 20 站 × 31 个月 × 3 源 = 1,860 个带侧车的月文件，目前只有南京 93 个；缺 1,767 个。旧目录中 1,860 个原始文件已完成离线字节/抓取日志/坐标核验，但历史日志没有完整请求 URL 与参数，不能伪造缺失侧车或直接把旧文件升级为当前协议缓存。
2. 因缺 19 站当前协议的 GFS 请求侧车，20 站返回服务坐标的完整 provenance 门槛仍不通过。
3. 20 站当前协议、独立按小时审计的 Himawari 真值收据仍缺。旧文件的离线审计发现 1,317 个白天真值缺测站-小时；训练/测试可用性不能写成 100%。
4. 除 raw GFS 外九个 CPU 模型在正式登记表仍为待验证；南京成功只能证明单站诊断执行，不等同于 20 站 validated/official 准入。

这四项没有通过前，不运行或宣称正式 20 站 benchmark；不补写旧侧车、不伪造真值、不借用测试集选参。`cpu_ready=blocked` 是保护正式结果身份的预期状态，不否定已完成的南京诊断结果。
